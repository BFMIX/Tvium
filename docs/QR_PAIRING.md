# Local QR pairing

Native Tvium apps can receive a source from a phone when the TV has no convenient keyboard. On wide first-launch screens the QR code appears beside the manual source options without an extra action. The TV binds a temporary HTTP listener to a private Wi-Fi or Ethernet IPv4 interface. VPN and virtual-adapter addresses are excluded because a nearby phone may not be able to reach them. If no suitable interface exists, the app shows a retry action. Narrow phone screens do not start a local pairing listener. Web builds use the HTTPS pairing flow instead.

The QR contains a random 256-bit session token and a local address. It contains no playlist URL or provider credential. The listener closes after one valid submission, screen disposal, or ten minutes. A valid submission starts M3U or Xtream import automatically. The screen shows the submitted source type during import and confirms success only after import completes. It does not show the URL or credentials. The phone page and responses use no-store headers and contain no external scripts or analytics.

The phone submits details directly to the TV over local HTTP. This avoids a cloud relay, but the transfer is not encrypted. Pair only on a trusted home network; do not use this flow on shared or public Wi-Fi. A future version can use authenticated encryption or a trusted relay before recommending pairing on untrusted networks.

Synthetic tests cover token routing, expiration, single-submission behavior, adapter selection, input validation, automatic import triggering, and 960×540 TV layout. Android TV and other physical-device pairing still need runtime validation, including LAN discovery and firewall behavior. Selecting an existing playlist from the installed phone app is planned; this QR currently opens the phone entry page.
